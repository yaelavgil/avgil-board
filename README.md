# לוח של האבגילים המשפצים

לוח המשימות המשותף של יעל ורועי — שיפוץ הבית שלנו, בית, בית ספר ובריאות.

**האפליקציה:** https://yaelavgil.github.io/avgil-board

**קנבן:** https://yaelavgil.github.io/avgil-board/tasks.html — אותן משימות בדיוק, במסך של
תהליך: שש עמודות (מאגר · מוכן לביצוע · בתהליך · ממתין לתשובה שלי · ממתין/חסום · בוצע),
עדיפות, אחראי ומדווח. ראו ״שני המסכים״ למטה.

## איך זה עובד

- עמוד אחד, `index.html`, בלי שלב בנייה ובלי תלויות.
- המשימות נשמרות ב-Firebase Realtime Database תחת `/board/tasks/<id>` — אותו פרויקט שמשרת את `lighting-map` ו-`reno-payments`.
- סנכרון חי דרך Server-Sent Events: מה שאחד מסמן בטלפון שלו מופיע אצל השני תוך שנייה, בלי התחברות.
- העמוד נטען עם עותק מוטמע של המשימות כדי שהציור הראשון יהיה מיידי, ואז מתעדכן מהרשת.

## מבנה משימה

```
id, title, notes, cat, due, list, order, done, owner, ongoing, pin, waTo, wa, updatedAt
st, pri, reporter                      ← נוספו בשביל הקנבן
```

- `cat` — trip / reno / home / gift / idea / school / health
- `owner` — יעל / רועי / שנינו. בקנבן זה ה-assignee.
- `ongoing: true` — משימה מתמשכת: קטגוריה משלה בראש הלוח, בלי תאריך יעד, אף פעם לא נספרת כאיחור.
- `st` — העמודה בקנבן: backlog / ready / doing / blocked / waiting-me / done
- `pri` — urgent / important / normal
- `reporter` — מי העלה את המשימה, בנפרד מ-`owner` שהוא מי מבצע

## שני המסכים

`index.html` ו-`tasks.html` הם שני מסכים על אותן רשומות ב-`/board/tasks/<id>` — לא שני
מסדים ולא שכפול. כל אחד מהם נכתב כך שלא ישבור את השני:

- `done`, `due`, `owner`, `items`, `notes` ו-`title` הם חוזה. קוראים אותם גם
  `likuyim.html` וגם `tools/build_ics.py`, שמוציא אירוע יומן רק למשימה עם `due`
  שאינה `done` ואינה `ongoing`, ולוקח את השעה מהמחרוזת `HH:MM` הראשונה ב-`notes`.
- `done` גובר על `st`. משימה שסומנה כבוצעה בלוח הישן נוחתת בקנבן בעמודת ״בוצע״
  גם אם `st` שלה נשאר מה שהיה.
- משימה שנוצרה בלוח הישן מגיעה בלי `st`/`pri`. הקנבן גוזר אותם מ-`list`/`done`
  באותו מיפוי שבו רצה המיגרציה החד־פעמית, כך שאין כרטיס בלי עמודה:
  `done` → בוצע · `ongoing` → בתהליך · `list` hot/now → מוכן לביצוע · השאר → מאגר;
  ו-`pri`: `list:hot` או `lv:1` → דחוף · `list:now` → חשוב · השאר → רגיל.
- הקנבן כותב ב-PATCH של השדות שהשתנו בלבד, ולכן אינו דורס שדה שנכתב באותו רגע
  מהטלפון השני ואינו יכול למחוק שדה שהוא לא מכיר.
